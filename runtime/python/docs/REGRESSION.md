# Regression testing as a workflow (M5)

> Replaying a recorded run is a test. If the runtime's behaviour drifts, the replay
> stops being byte-identical (or its eval case stops passing) and the build fails.

A KEEL run is an append-only event log that already carries its model responses and
tool outputs (M1/M4). That makes a recorded run a complete, self-contained regression
fixture: you can replay it later, with **no API key and no network**, and assert that
the runtime still produces the exact same event log. M5 turns that property into a CI
gate.

## What a regression bundle is

A *regression bundle* is one JSON file (`keel.regression/1`) holding everything needed
to replay a run standalone:

| field | meaning |
|-------|---------|
| `graph` | the KIR graph that was run |
| `events` | the full recorded event log |
| `blobs` | every blob the log references, inlined as base64 |
| `eval_case` | *(optional)* assertions over step outputs (an `EvalCase`) |

Bundles are plain, reviewable JSON — a diff shows exactly what changed.

## Two regressions it catches

1. **Determinism drift.** The bundle no longer replays byte-identically — a change
   leaked nondeterminism, reordered the log, or altered serialization or cost. This is
   the core durable-execution guarantee; any drift fails the suite.
2. **Behavioural drift.** The optional eval case (assertions over recorded step
   outputs) no longer passes — e.g. output extraction, validation, or scoring changed.

A bundle whose eval case is merely *flaky* (an LLM-judge assertion, say) is reported as
skipped, not failed.

## Capture and run

```bash
# Capture a recorded run into a portable bundle (optionally embed an eval case).
keel regress record <run_id> --out tests/regression/suite/my-run.json [--case eval.json]

# Replay a directory of bundles; exit non-zero on any regression.
keel regress run --suite tests/regression/suite --junit regression-junit.xml
```

## In CI

KEEL dogfoods this. `.github/workflows/regression.yml` replays the committed suite
under `tests/regression/suite/` on every pull request and push to `main`, and blocks
the merge on any drift. The dogfood suite is generated by
`python -m tests.regression._gen_suite` (a linear pipeline, a fan-out/fan-in branch,
and a pipeline with an embedded eval case) and is the source of truth — regenerating it
must produce byte-stable artifacts.

### Use it in your own repo

A reusable composite action ships at `.github/actions/keel-regress`:

```yaml
- uses: actions/checkout@v4
- uses: actions/setup-python@v5
  with: { python-version: "3.11" }
- run: pip install keel
- uses: Bobcatsfan33/keel/.github/actions/keel-regress@main
  with:
    suite: tests/regression/suite
```

Capture bundles from your real runs, commit them, and the action will hold your agents
to byte-identical replay on every PR.
