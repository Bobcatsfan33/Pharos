**Exit gate (measured in [benchmarks/latency.md](../benchmarks/latency.md#tier-1-mandate-token-path-workstream-a)):**

## Construction

Adopted from the Biscuit specification, reimplemented in `packages/core`, no library, no
Datalog. Checks are Pharos rule-citation JSON.

- **Authority block** — canonical JSON of the mandate (tenant, agent, mandate id, grantor,
  issued/expires, `scope.actionTypes`, `scope.resources`, `limits`, rule citations, the root
  `keyId`, and `nextKey`: the raw Ed25519 public key of the first ephemeral keypair) signed by the
  tenant's **mandate key** (`mandate:<tenantId>`) through the existing `SigningProvider`. The
  root key is published in the ordinary `/v1/keyset`, so a verifier needs nothing but the keyset.
- **Attenuation block** — `checks[]` of kind `limit | expiry | scope`, each of which can only
  narrow; `issuedAt`; `nextKey` for the following block. Signed with the previous block's
  ephemeral private key, which the attenuator then discards.
- **Proof** — the token carries either the current ephemeral private key (`{ kind: "next" }`,
  attenuable) or a final signature by it (`{ kind: "sealed" }`, not attenuable). This is the
  one deliberate addition to the handoff's sketch: without a proof, a verifier cannot tell a
  truncated chain (blocks dropped = scope widened) from a shorter honest one. Biscuit solves
  truncation exactly this way, and so does this codec.
- **Signing messages** are domain-separated and position-bound:
  `pharos:mandate-token:v1:authority\n<sha256(canonical(authority))>` and
  `pharos:mandate-token:v1:block\n<index>\n<previous block hash>\n<sha256(canonical(block))>`.
  A block cannot be reordered, replaced, or spliced from another token.
- **`verify(token, rootKey, now)`** is pure and offline: shape → root signature → each block's
  signature against the key the prior block published → no ephemeral key reused → every check
  narrows the effective authority so far (structural rejection, not policy) → proof matches the
  head → not expired at `now`. It returns the effective authority and the block hashes.
- **`effective(token)`** is the intersection: smallest limit, earliest expiry, narrowest scope.

Canonical JSON is the repo's existing canonicalizer (`packages/core/src/chain/canonical.ts`).
For the values a token contains (strings, finite numbers, arrays, objects) it is byte-identical
to RFC 8785: sorted keys by UTF-16 code units, `JSON.stringify` number and string forms, no
whitespace. No second implementation.

## Decisions made while implementing

- **Canonical base64 and an exact proof shape.** A lenient base64 decoder let two strings name
  one signature, and the proof (the one part outside the head hash) accepted extra keys; both
  would have given one token two head hashes. The shape check now rejects non-canonical base64
  anywhere and any proof key beyond `kind` + `secret` / `signature`. The fuzz suite asserts
  that every byte change to a valid token is refused, across at least four distinct codes.
- **`mint` audit action.** Minting a token is recorded in the access audit; the
  `AccessAction` type gained `"mint"` (the column is free text; no migration).
- **Vectors expire in 2035/2036** so the SDK tests that use the real clock stay valid; the
  `expired` vector pins its own clock.
- **Vitest include** gained `packages/core/test/**/*.test.ts`; nothing about the zero-skip
  gate changed.
- **ADR numbering** uses 0007; 0006 is reserved by the open adoption-program PR (#290).

## What stays honest

- Offline verification proves signature validity and narrowing. It cannot see revocation of
  the stored mandate; only the server checks that, at submit time.
- Local allow never replaces the sealed verdict. It is off by default.
- Throughput is a Tier-1-only number on one process; it says nothing about Tier 3.
