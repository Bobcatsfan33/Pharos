# D1 plan — structural judges, routing, parallel panel (Sprint S1)

Workstream D1 of the
[judgement family and primitives handoff](2026-10-29-judgement-family-and-primitives.md).
This is the plan the kickoff asked for, written before the code and kept in step with what
landed. Branch `s1-d1-structural-judges-routing`, based on `main@9c1f14e`.

**Exit gate (measured in [benchmarks/latency.md](../benchmarks/latency.md#judge-path-d1)):**
judge-path p99 for a `crm.update` with no applicable models < 20 ms; the three-model path runs
in max(model), not sum(model); routing tests. Judge promotion status is untouched.

## How `verdict.latency.perTier` carries per-judge timings

`ActionRecord` v1 is frozen and `verdict.latency.perTier` is `Record<string, number>`. The
handoff wrote `perTier["3"].perJudge`, which would change the value type and break every
sealed record and fixture. Instead:

- `perTier["3"]` stays a number: the tier's wall time, as before.
- Each judge adds a flat sibling key `perTier["3/<judgeId>"]` with its own milliseconds
  (`3/structural`, `3/finra-promissory`, `3/phi-in-context`, `3/funds-movement-intent`).
- `totalMs` and the fail-mode arithmetic sum only keys without a `/`, so existing fixtures
  that assert `totalMs ≈ perTier["1"] + perTier["2"] + perTier["3"]` still hold.
- The verdict fingerprint already excludes `latency`, so replay is unaffected.
- No schema bump, no ADR: the map's declared type is unchanged and the new keys are additive.

Old records without the keys read exactly as before. The absence of a `3/<model>` key is
itself evidence that routing did not run that model.
